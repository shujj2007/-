# 照片按拍摄时间自动重命名工具

一个用 Python 编写的工具：读取照片 EXIF 中的**拍摄时间**
（优先 `DateTimeOriginal`），并按你自定义的格式批量重命名照片。
支持 JPEG / PNG / WebP / TIFF / HEIC 以及常见 RAW 格式（CR2 / NEF / ARW / DNG 等）。

提供两种使用方式：

- **命令行版** `photo_renamer.py` —— 适合批量、脚本化、定时任务
- **图形界面版** `photo_renamer_gui.py` —— 适合日常手动操作，所见即所得

## 图形界面版（推荐日常使用）

```bat
pip install Pillow exifread
python photo_renamer_gui.py
```

界面功能：

- 点击「浏览…」选择照片目录
- 命名格式直接输入，或从下拉框选择常用预设
- **「星期显示」下拉框**：不显示 / 周一 / 星期一 / Mon / Monday，一键加入格式
- **「小时制」下拉框**：24 小时制（`%H`）/ 12 小时制（`%I`）/ 12 小时制 + 时段词（`%p%I`，自动选择凌晨/上午/中午/下午/晚上，在小时前）
- **时段划分**：凌晨 0–5 点 / 上午 6–10 点 / 中午 11–12 点 / 下午 13–18 点 / 晚上 19–23 点；小时统一两位（`凌晨00点` ~ `晚上12点`）
- 勾选：递归子目录 / 无 EXIF 跳过 / 复制模式（保留原文件）
- 点击「① 预览」查看改名结果，确认无误后点「② 执行重命名」
- 双击列表行可打开所在文件夹；重名自动追加 `_1`/`_2`，绝不覆盖
- **结果列表彩色区分**：
  - 🔵 蓝色 = 识别到时间、需要改名
  - 🟢 绿色 = 新名称与原名称相同，自动跳过
  - 🔴 红色 = 未识别到拍摄时间（勾选"无 EXIF 跳过"时）
- **识别进度条**：预览扫描时底部进度条实时显示识别百分比（识别拍摄时间 / 执行改名都有）

> 需要 Python 自带 Tkinter（Windows 官方安装包默认包含）。

## 打包成 exe（免安装 Python 直接运行）

每次发布新版本只需两步：

1. 修改源码中的版本号（`photo_renamer.py` 和 `photo_renamer_gui.py` 顶部的 `__version__ = "x.y.z"`）
2. 运行打包：

```bat
pip install pyinstaller
python build_exe.py
```

或者直接双击 **`打包.bat`**。

产物在 `dist` 目录：

| 文件 | 说明 |
| --- | --- |
| `photo_renamer_v1.0.0.exe` | 命令行版（带控制台窗口） |
| `photo_renamer_gui_v1.0.0.exe` | 图形界面版（无控制台窗口，双击即用） |

> 打包为单文件（onefile），拿到任何 Windows 电脑上都能直接运行，
> 无需安装 Python 或任何依赖。

## 从文件名识别拍摄时间（无 EXIF 照片）

有些老照片/截图没有 EXIF，但文件名本身包含了拍摄时间（如 `IMG_20230101_123456.jpg`）。
工具支持把这些照片**按名称类型分组**，尝试从名称中提取时间，并由你确认后自动套用到同类型照片。

### GUI 操作流程

1. 勾选「无 EXIF 时从文件名识别时间」（默认开启）
2. 点击「① 预览」：扫描完成后，若存在无 EXIF 的照片，会弹出**分组确认窗口**：
   - 每行 = 一种名称类型（含示例文件名、数量、自动猜测的时间），**按照片数量从多到少排列**
   - **单张且未识别出时间的照片自动并入「其它」分组**（恒排在最后，此类照片需手动处理）
   - **支持多选**（Ctrl/Shift+点击）：选中多组后点「确定所选组」可一次采用各组猜测；也可点「全选」一键全确认
   - 选中某组，可**直接修改**时间（格式 `YYYY-MM-DD HH:MM:SS`）后点「确定该组」
   - 点「完成」后，工具会**反推该类型名称中哪几段数字对应年月日/时分秒**（如
     `第1段(年4位, 月2位, 日2位)，第2段(时2位, 分2位, 秒2位)`），并自动应用到同类型的其他照片
3. 回到主界面查看预览：识别出的照片显示「待重命名（名称识别）」，确认后执行

> 无法从名称提取时间的文件（如月份=13 的非法日期）会保持红色跳过；
> 取消对话框则所有无 EXIF 照片退回"文件修改时间"或"跳过"策略。

### CLI 用法

```bat
:: 交互模式：逐个分组确认/修改
photo_renamer_v1.4.0.exe D:\Photos --name-fallback

:: 自动模式：直接采用自动猜测（-y 跳过确认）
photo_renamer_v1.4.0.exe D:\Photos --name-fallback -y
```

支持识别的名称形态举例：`20230101_123456`、`IMG_2023-01-01_08-15-30`、
`2023年01月01日 12时34分56秒`、两位年份 `230101_123456`、带序号后缀
`IMG_20230101_123456_01`、时间戳命名（微信导出 `mmexport<13位毫秒时间戳>`）等；
反推规则支持任意分隔符与数字段位置，即使名称中混有无关数字段也能自动定位。

## 功能特性

- 自动读取 EXIF 拍摄时间（DateTimeOriginal → DateTimeDigitized → DateTime）
- 命名格式完全自定义（strftime 占位符 + `{orig}` / `{ext}`）
- 支持递归处理子目录（`-r`）
- 支持在格式中写路径分隔符，**按日期自动归档到子目录**
- 无 EXIF 时默认回退到文件修改时间（可用 `--no-fallback` 改为跳过）
- 重名自动追加 `_1` / `_2` 后缀，**绝不覆盖已有文件**
- `--action copy` 复制模式：生成新名称文件，保留原文件
- `-n` 预览模式 + 执行前确认，防止误操作
- 自动清理文件名中的非法字符（`<>:"|?*`）

## 安装

需要 Python 3.8+，然后安装依赖：

```bat
pip install Pillow exifread
```

可选依赖：

```bat
pip install pillow-heif    :: 支持 HEIC/HEIF 格式
```

> 不安装任何依赖也能运行，但读不到 EXIF，会全部回退到文件修改时间。

## 使用方法

```bat
python photo_renamer.py <目录> [选项]
```

### 常用选项

| 参数 | 说明 |
| --- | --- |
| `-f, --format` | 命名格式，默认 `%Y%m%d_%H%M%S` |
| `-r, --recursive` | 递归处理子目录 |
| `-e, --ext` | 只处理指定扩展名，如 `-e jpg jpeg png` |
| `--action copy` | 复制为新名称，保留原文件（默认 rename 直接重命名） |
| `--no-fallback` | 无 EXIF 时跳过，不使用文件修改时间 |
| `-n, --dry-run` | 只预览，不实际执行 |
| `-y, --yes` | 不询问直接执行 |
| `-v, --verbose` | 输出详细信息 |
| `-j, --jobs` | 并行读取 EXIF 的线程数（`0`=按 CPU 自动，`1`=单线程，默认 1） |
| `--no-color` | 关闭彩色输出（终端显示时默认自动彩色） |
| `--no-progress` | 关闭识别进度百分比显示（终端显示时默认自动显示） |
| `--name-fallback` | 无 EXIF 的照片尝试从文件名识别拍摄时间（按名称类型分组确认；`-y` 时自动采用猜测值） |

命令行版的输出同样有颜色区分：**蓝色**=待改名，**绿色**=名称相同跳过，**红色**=无 EXIF 时间。
识别过程中终端会实时刷新进度百分比（如 `识别进度: 42.3% (4234/10000)`，超过 20 个文件时显示）。

## 性能：上万张照片没问题

在 Windows 11 + SSD 上实测（10,001 个文件，全部同一拍摄时间、全部重名冲突的最坏情况）：

| 环节 | 耗时 |
| --- | --- |
| 扫描目录 | 0.1 秒 |
| 读取 EXIF + 生成改名计划 | 约 1.7 秒 |
| 执行重命名（含 1 万个重名冲突处理） | 约 1.9 秒 |
| GUI 列表显示 1 万行 | 0.13 秒 |

也就是说 **1 万张照片全流程约 4 秒**，10 万张约 40 秒左右（取决于磁盘）。

针对大规模做了专门优化：

- **重名冲突 O(1) 处理**：对同秒/同日大量照片自动追加 `_1`/`_2` 后缀采用
  "目录快照 + 序号续接"算法，不会因文件多而指数变慢
- **并行读取 EXIF**：机械硬盘、网络盘等读取慢的场景，可用 `-j 8`（或 GUI
  的"并行线程"选项）提升数倍速度
- **预览/执行异步处理**：GUI 扫描、重命名都在后台线程，处理 1 万张时界面不卡

> 注意：`--action copy` 复制模式会把文件真实复制一遍，速度受磁盘写入速度
> 限制（1 万张 × 每张 5MB ≈ 50GB 写入），这是复制本身的开销，与工具无关。

## 格式占位符

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `%Y` | 四位年份 | 2024 |
| `%y` | 两位年份 | 24 |
| `%m` | 月份（补零） | 01-12 |
| `%d` | 日（补零） | 01-31 |
| `%H` | 小时（24 小时制） | 00-23 |
| `%I` | 小时（12 小时制，统一两位；凌晨 0 点显示为 `00`） | 00-12 |
| `%p` | 中文时段词（按时段自动选择） | 凌晨 / 上午 / 中午 / 下午 / 晚上 |
| `%M` | 分钟 | 00-59 |
| `%S` | 秒 | 00-59 |
| `%f` | 微秒 | 123456 |
| `%j` | 年内第几天 | 001-366 |
| `%a` / `%A` | 星期简写 / 全写（英文） | Mon / Monday |
| `%b` / `%B` | 月份简写 / 全写 | Jan / January |
| `%%` | 字面 `%` | % |
| `{orig}` | 原文件名（不含扩展名） | IMG_001 |
| `{ext}` | 原扩展名（不含点） | jpg |
| `{week}` | 中文星期简写 | 周一 ~ 周日 |
| `{weekfull}` | 中文星期全写 | 星期一 ~ 星期日 |

## 示例

```powershell
# 默认格式重命名当前目录（YYYYMMDD_HHMMSS）
python photo_renamer.py .

# 自定义格式，带前缀
python photo_renamer.py D:\Photos -f "IMG_%Y%m%d_%H%M%S"

# 保留原名 + 拍摄时间
python photo_renamer.py D:\Photos -f "%Y%m%d_%H%M%S_{orig}"

# 按日期归档到子目录（自动创建目录）
python photo_renamer.py D:\Photos -f "%Y\%m\%d_%H%M%S"

# 中文长格式（GUI 预设之一）
python photo_renamer.py D:\Photos -f "%Y年%m月%d日{weekfull}-%p%I点%M分%S秒"
:: 结果: 2020年07月25日星期六-晚上09点41分47秒.jpg

# 递归 + 预览，确认无误再执行
python photo_renamer.py . -r -n
python photo_renamer.py . -r -y

# 复制模式，不修改原文件
python photo_renamer.py D:\Photos --action copy -f "copy_%Y%m%d_%H%M%S"

# 只处理指定扩展名，且无 EXIF 的照片跳过
python photo_renamer.py D:\Photos -e jpg jpeg --no-fallback
```

> 在 PowerShell 中格式串用单引号包裹可避免转义问题，例如
> `python photo_renamer.py . -f '%Y\%m\%d_%H%M%S'`。

## 注意事项

- 重名时自动追加 `_1`、`_2` 后缀，不会覆盖已有文件。
- 格式中的 `/` 和 `\` 视为路径分隔符，会创建子目录实现按日期归档；
  其他非法字符（`<>:"|?*`）会被替换为下划线。
- 无 EXIF 的照片默认使用文件修改时间，可加 `--no-fallback` 改为跳过。
- EXIF 时间通常是相机设置的本地时间，重命名按本地时间处理。
- 建议先加 `-n` 预览确认，再正式执行。

## 常见问题

- **HEIC 打不开？** 安装 `pip install pillow-heif`。
- **RAW 读不到拍摄时间？** 安装 `exifread`；个别机型 RAW 无 EXIF 时会使用文件修改时间。
- **想按日期整理到文件夹？** 在格式中使用路径分隔符即可，如
  `-f "%Y\%m"` 会把照片放进 `2024\01\` 子目录。
- **运行提示没有 Pillow/exifread？** 先执行 `pip install Pillow exifread`。
